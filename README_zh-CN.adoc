= CodexPlusPlus on Linux
:toc:
:toclevels: 2

link:README.adoc[English] | 简体中文

`CodexPlusPlus-on-Linux` 是面向 `BigPizzaV3/CodexPlusPlus` 的源码级 Linux 适配项目。
它记录并重新应用必要补丁，使 Codex++ 可以配合 `ilysenko/codex-desktop-linux` 生成的非官方 Linux Codex Desktop 构建使用。

项目版本：`1.2.41`，与上游 Codex++ `v1.2.41` 同步。

本仓库作为下列项目的 fork/适配版本维护：

* Codex++ 上游项目： https://github.com/BigPizzaV3/CodexPlusPlus
* Linux Codex Desktop 打包参考： https://github.com/ilysenko/codex-desktop-linux

许可证：GPL-3.0-or-later。
参见 link:LICENSE[LICENSE]。

== 本仓库提供什么

* `docs/` 下的 Antora 文档组件。
* `docs/modules/ROOT/pages/snippets.adoc` 中的结构化片段清单。
* `docs/modules/ROOT/pages/maintenance-workflow_zh-CN.adoc` 中的正式维护流程。
* `docs/modules/ROOT/pages/adapter-workflow_zh-CN.adoc` 中的历史/实验性定期适配工作流。
* `docs/modules/ROOT/attachments/patches/` 中的补丁附件。
* 双语 PowerShell 安装与管理脚本：`scripts/developer/Installer-and-Manager.ps1`。
* `CodexPlusPlus/src` 和 `codex-desktop-linux/src` 下的上游源码快照，供研究和可复现对照使用；嵌套 `.git` 元数据和本地构建缓存有意不纳入跟踪。

管理脚本可从原始 Codex++ 源码包安装、更新、卸载并重新应用 Linux 适配。

== 预期的 Linux Codex Desktop 布局

默认情况下，脚本可接受仓库式布局：

[source,text]
----
$HOME/opt/codex-desktop-linux/codex-app/start.sh
$HOME/opt/codex-desktop-linux/codex-app/version
----

也可接受本项目验证工作流使用的直接 app-root 布局：

[source,text]
----
$HOME/opt/CodexDesktop/start.sh
$HOME/opt/CodexDesktop/version
----

默认 Codex++ 适配器安装路径为已识别 Codex app 目录下的 `.codex-plusplus`。
例如：

[source,text]
----
$HOME/opt/codex-desktop-linux/codex-app/.codex-plusplus
$HOME/opt/CodexDesktop/.codex-plusplus
----

== 先安装 Linux Codex Desktop

安装本适配器之前，请先按照 https://github.com/ilysenko/codex-desktop-linux 的 `README.md` 操作。
下面的命令是一个实用示例；当前平台所需依赖和要求请以该上游 README 为准。

[source,powershell,subs="attributes,macros"]
----
$adapterRoot = "$HOME/opt/CodexPlusPlus-on-Linux"
$codexDesktopInstallPath = "$HOME/opt/CodexDesktop"

Set-Location $adapterRoot
pwsh ./scripts/developer/Build-CodexDesktopLinux.ps1 `
    -Action build-install `
    -SourceRoot "$adapterRoot/codex-desktop-linux/src" `
    -InstallPath $codexDesktopInstallPath

New-Item -ItemType Directory -Force -Path "$HOME/.local/bin", "$HOME/.local/share/icons", "$HOME/.local/share/applications"
New-Item -ItemType SymbolicLink -Force `
    -Path "$HOME/.local/bin/codex-desktop-linux" `
    -Target (Join-Path $codexDesktopInstallPath 'start.sh' -Resolve)
New-Item -ItemType SymbolicLink -Force `
    -Path "$HOME/.local/share/icons/codex-desktop.png" `
    -Target (Join-Path $codexDesktopInstallPath '.codex-linux' 'codex-desktop.png' -Resolve)

$desktopFilePath = "$HOME/.local/share/applications/codex-desktop-linux.desktop"
Copy-Item -Path "contrib/user-local-install/files/.local/share/applications/codex-desktop.desktop" -Destination $desktopFilePath -Force
(Get-Content $desktopFilePath) -creplace '^Exec=.*', 'Exec=codex-desktop-linux' | Set-Content $desktopFilePath

----

构建脚本会动态发现固定版 `codex-desktop-linux` 源码中除
`example-feature` 与 `local` 之外所有带描述文件的顶层 feature，写入 gitignored
的 `linux-features/features.json`，同时导出 `CODEX_LINUX_FEATURES` 和
`CODEX_LINUX_FEATURES_CONFIG`，并要求两份 build-info 文件精确记录发现结果。
`v1.2.41` 基线当前可发现 29 个 Linux features；若出现
`Enabled features: None`，构建会直接判定失败。

`ydotool` 的安装命令本身因发行版而异；当前包名和服务配置请参考 `ilysenko/codex-desktop-linux` 的 `docs/linux-computer-use.md`。

如果要更新 Linux Codex Desktop 构建，请替换 `ilysenko/codex-desktop-linux` 使用的 `Codex.dmg`，然后重新执行同一 PowerShell 构建流程。

== 安装适配后的 Codex++

使用 PowerShell 运行管理脚本：

[source,powershell]
----
pwsh ./scripts/developer/Installer-and-Manager.ps1 -Action install -CodexDesktopRootPath "$HOME/opt/CodexDesktop"
----

脚本默认值保持保守：

* Codex Desktop 根目录：`$HOME/opt/codex-desktop-linux`
* Codex++ 源码：拉取 `https://github.com/BigPizzaV3/CodexPlusPlus`
* Codex++ 安装路径：已识别 Codex app 目录下的 `.codex-plusplus`
* 回归测试片段：启用
* 更新检查提示：默认禁用

启用 desktop entries 时，脚本会创建贴近上游行为的用户级入口
`$HOME/.local/share/applications/codex-plus-plus.desktop` 和
`$HOME/.local/share/applications/codex-plus-plus-manager.desktop`。
它们的显示名称为 `Codex++` 和 `Codex++ Manager`，会在可用时复用 Linux Codex Desktop 图标，并替换旧的适配器品牌 `*-linux.desktop` 入口。
安装和更新还会迁移历史遗留的无图标 `codex-desktop-linux.desktop`
模板，但只有名称、启动命令和未展开的 `@HOME@` `TryExec` 三个原始标记
同时匹配时才会删除；仅文件名相同的自定义入口会被保留。

脚本顶部有配置区。
它支持 shell 风格路径值，例如 `$HOME/opt/CodexDesktop`、`${HOME}/opt/CodexDesktop`、`$env:HOME/opt/CodexDesktop` 和 `~/opt/CodexDesktop`。

== 更新适配后的 Codex++

[source,powershell]
----
pwsh ./scripts/developer/Installer-and-Manager.ps1 -Action update -CodexDesktopRootPath "$HOME/opt/CodexDesktop"
----

`update` 操作会拉取或复制一份新的上游源码，重新应用已启用片段，重新构建，并替换已安装的适配器二进制文件。

== 卸载适配后的 Codex++

[source,powershell]
----
pwsh ./scripts/developer/Installer-and-Manager.ps1 -Action uninstall -CodexDesktopRootPath "$HOME/opt/CodexDesktop"
----

默认会保留用户脚本。
如果需要完整清理，请修改脚本配置区中的 `$PreserveUserScriptsOnUninstall`。
