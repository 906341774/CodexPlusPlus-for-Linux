== Post-install hotfix notes

Date: 2026-07-03

Host verification after manually applying the v1.2.28 build exposed a stale-path case:

* The real Linux Codex Desktop root was `$HOME/opt/CodexDesktop` with `start.sh` and `version` directly under that directory.
* Existing user state still contained the older nested `$HOME/opt/CodexDesktop/codex-app` path in both Codex++ state and manager settings.
* The generated `codex-plus-plus.desktop` entry and `launch-codex-plus-plus` wrapper still carried the correct app root.

The `010-linux-app-paths` patch was extended so the runtime resolver first honors explicit and valid saved paths, then recovers from adapter state, and finally can recover the real app root from the adapter desktop entry and wrapper when stale `codex-app` state is present.

The `900-regression-tests` patch now includes `app_paths_linux_recovers_from_stale_state_using_adapter_desktop_entry` to keep this recovery path covered.

== Post-install local thread catalog hotfix

Date: 2026-07-05

Host debugging confirmed that incomplete Codex Desktop project conversation lists are a `v1.2.28` Linux compatibility issue rather than a GUI test infrastructure issue.

Observed symptom:

* Codex++ Manager listed local session history for affected workspaces.
* Codex Desktop showed the same projects with an empty conversation state, especially for opened-folder projects.

Root cause:

* Provider sync could backfill `local_thread_catalog` rows but treated rows already marked `missing_candidate = 1` as current when the remaining fields matched.
* Codex Desktop full-scan pruning could mark or delete provider-sync backfilled `source_kind = 'rollout'` rows when the Linux full scan did not rediscover those rollout files directly.

Fix scope:

* `080-linux-local-thread-catalog-sync` now backfills local catalog rows and restores rows marked `missing_candidate` during provider sync.
* The Linux Codex Desktop ASAR patch registry now patches the local thread catalog startup and pruning paths:
  `linux-local-thread-catalog-initial-snapshot` and `linux-local-thread-catalog-preserve-backfill`.
* `900-regression-tests` now covers provider-sync backfill, `missing_candidate` restoration, and local thread catalog visibility regressions.

Validation:

* `cargo test -p codex-plus-data --test provider_sync -- --nocapture`
* `node --test codex-desktop-linux/src/scripts/patch-linux-window-ui.test.js`
* Host SQLite check after provider sync showed affected project rows with `missing_candidate = 0`.
* Host UI check showed an affected project displaying real session history instead of the empty conversation state.
