= Codex++ v1.2.28 Fast service-tier hotfix
:toc:
:toclevels: 2

Date: 2026-07-08

== Scope

This note records the `v1.2.28-fix-0004` hotfix for the Codex++ injected `Fast` / `Standard` service-tier badge on Linux Codex Desktop.

The maintainer reported that clicking the Codex++ badge showed:

[source,text]
----
Fast 仅支持 gpt-5.4 / gpt-5.5，当前模型未获取
----

The same window showed the upstream Codex Desktop model selector with `5.5 超高` and the upstream Fast menu, so the model was available to the renderer even though Codex++ could not read it through its own backend catalog.

== Root Cause

The Codex++ renderer injection only accepted the current Fast-capable model from:

* the intercepted request payload, or
* `/codex-model-catalog`, which is derived from Codex++ relay/config state.

That misses the current upstream Codex Desktop active model in ChatGPT or official desktop flows where the selected model is represented in the composer footer and upstream React state instead of Codex++ config.

As a result, the local badge click path rejected Fast before any request was sent, even when the visible upstream model was `5.5 超高`.

== Fix

`assets/inject/renderer-inject.js` now has a narrow model fallback:

* preserve explicit catalog/request model priority;
* keep blocking Fast when the catalog explicitly reports an unsupported model such as `gpt-4.1`;
* when catalog and request model are empty, inspect only visible composer/footer candidates;
* canonicalize supported labels such as `GPT-5.5` or `5.5 超高` to `gpt-5.5`.

The request override still sends Fast only for the supported set:

[source,text]
----
gpt-5.4
gpt-5.5
----
