= Codex++ v1.2.28 host regression hotfix
:toc:
:toclevels: 2

Date: 2026-07-07

== Scope

This note records the host regressions found after the `v1.2.28` Linux adaptation and the fixes that must remain attached to the `v1.2.28` baseline.

The affected host install was rooted at:

[source,text]
----
$HOME/opt/CodexDesktop
----

The hotfix target is `v1.2.28-fix-0003`.

== Findings

=== Codex++ version regressed to 1.2.25

The manager UI showed `Codex++ 1.2.25` even though the adaptation round and installer script were pinned to `v1.2.28`.

Evidence:

* `$HOME/.local/share/codex-plusplus/state.json` recorded `"version": "1.2.25"` during the earlier host repair.
* The installed binaries under `$HOME/opt/CodexDesktop/.codex-plusplus/install/` contained `CodexPlusPlus/1.2.25`.
* The vendored workspace `CodexPlusPlus/src/Cargo.toml` still declared `version = "1.2.25"`.

Root cause:

* A host-side repair rebuilt from the vendored source tree whose workspace version had not been updated to the pinned `v1.2.28` baseline.
* The installer script's pinned version variable was correct, but the repository did not have a workflow assertion that the vendored Cargo workspace version matched it.

Fix:

* Keep `CodexPlusPlus/src/Cargo.toml` at `version = "1.2.28"`.
* Keep the workflow contract assertion that the vendored workspace version matches the current pinned upstream version.

=== Linux features showed None

The Codex Desktop LinuxDesktop settings tab showed `Enabled features: None`.

Evidence:

* Before this hotfix, `$HOME/opt/CodexDesktop/.codex-linux/build-info.json` and `resources/codex-linux-build-info.json` both contained an empty `linuxFeatures.enabled` list.
* The Podman build script already exported `CODEX_LINUX_FEATURES`, so the build script was not the root cause.
* Running the feature helper directly without a config file reproduced the empty result before the fix.

Root cause:

* `codex-desktop-linux/src/scripts/lib/linux-features.js` read `CODEX_LINUX_FEATURES_CONFIG` and config files, but ignored `CODEX_LINUX_FEATURES` during direct `make build-app` style builds unless a config file existed.
* The restored Podman image also lacked the Codex CLI even though the current fixture requires it. The running debug container was repaired with `npm install -g @openai/codex`; the repository fixture now asserts `@openai/codex` as a required runtime dependency.

Fix:

* Add environment feature parsing to `linux-features.js`.
* Merge `CODEX_LINUX_FEATURES` with configured features and apply `CODEX_LINUX_DISABLE_FEATURES` as a final filter.
* Add a regression test for direct install builds that rely on `CODEX_LINUX_FEATURES`.

=== Visible source-less conversations showed as empty history

The maintainer still observed many `暂无对话` entries after the first local catalog repair.

Evidence:

* The provider sync repair originally marked source-less rows missing only when `host_id = 'local'`.
* Remaining visible rows with empty `source_detail` belonged to remote SSH hosts.
* These rows had no rollout source and therefore could not be opened, but they could still remain visible as empty history entries.

Root cause:

* The local-only filter in `count_unopenable_local_thread_catalog_rows` and `mark_unopenable_local_thread_catalog_rows_missing` left remote source-less `local_thread_catalog` rows visible.

Fix:

* Remove the `host_id = 'local'` restriction when marking source-less visible catalog rows missing.
* Keep valid local rollout-backed rows visible and restored.
* Add regression coverage for remote source-less catalog rows.

=== Installed binary verification failed falsely

The container installer completed patching and building but failed during the final installed binary marker check:

[source,text]
----
Installed binary verification failed: Linux launcher wrapper cleanup marker was not found
----

Root cause:

* `Assert-InstalledLinuxAdaptationApplied` looked for the literal `launch-codex-plus-plus` inside the optimized `codex-plus-plus` release binary.
* The optimized binary no longer keeps that wrapper filename literal even though the Linux launcher behavior is present.

Fix:

* Keep source-level checks for the wrapper filename in `watcher.rs`.
* Change installed binary verification to check the release-stable `launcher.provider_sync_launch_timeout` marker.
* Add a workflow contract assertion so future installer checks keep using a release-stable provider sync marker.

== Classification

The catalog and route-opening fixes are `v1.2.28` compatibility fixes because they compensate for Codex Desktop storage and webview route behavior observed with the `v1.2.28` adaptation baseline.

The Linux features fix is a Codex Desktop Linux build-provenance bug: the build script requested features, but the helper ignored the environment-only feature list.

The installed binary marker fix is an installer validation bug: the installed binary was correct, but the previous check used an unstable optimized-release string.
