== Release notes reviewed

=== v1.2.26

Source: https://github.com/BigPizzaV3/CodexPlusPlus/releases/tag/v1.2.26[]

* Removed the special plugin forced-install feature while keeping plugin marketplace unlock behavior.
* Updated Codex++ icon resources.
* Fixed `config.toml` UTF-8 BOM parse/write compatibility.
* Upstream validation listed `node tools/i18n-verify.mjs`, `npm run check`, `cargo test -p codex-plus-core`, and `npm run build`.

Linux adapter impact:

* The `050-pure-api-config-sync` patch was kept and rebased so live Codex config writes normalize BOM-prefixed TOML before validation and writeback on every platform, not only Windows.
* Desktop-entry icon behavior remains governed by `040-linux-entrypoints-health`, which intentionally preserves upstream-style Codex++ launcher names and descriptions on Linux.

=== v1.2.27

Source: https://github.com/BigPizzaV3/CodexPlusPlus/releases/tag/v1.2.27[]

* Fixed session move failures caused by stale frontend asset hashes in newer Codex builds.
* Fixed session move paths that selected old SQLite databases and then reported `Thread not found`.
* Fixed stale project state and provider sync restoring old `cwd` after moving sessions back to normal conversations.
* Improved diagnostics around session move failures.
* Upstream validation listed `node tools/i18n-verify.mjs`, `npm run check`, `cargo test -p codex-plus-core`, `cargo test -p codex-plus-data`, and `npm run build`.

Linux adapter impact:

* The provider sync area changed enough that the Linux adapter needed an additional compatibility patch for Codex Desktop's new `local_thread_catalog` tables.
* The user-visible symptom is that Codex++ Manager can still list local sessions while Linux Codex Desktop project sidebars show an empty conversation state.
* The new `080-linux-local-thread-catalog-sync` patch backfills the newer local catalog from legacy `threads` rows during provider sync, excluding archived, projectless, and non-user-event threads.
