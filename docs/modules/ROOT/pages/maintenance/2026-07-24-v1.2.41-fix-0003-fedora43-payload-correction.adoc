== Root causes and fixes

=== Debian compatibility payload was used as a modern host payload

The earlier artifact set treated the Debian 10 build as a generally portable
host build. Runtime feedback showed severe animation, GPU, locale, Manager,
window-decoration, and conversation-list regressions that were not present in
the older AlmaLinux build.

The correction separates build products by target instead of treating the
lowest glibc build as the best runtime for every system:

* Debian 10 produces only the DEB line.
* AlmaLinux 9.8 produces the RHEL 9 RPM and compatible portable line.
* Fedora 43 produces the modern portable and host line.

=== Upstream DMG drifted during the maintenance round

The first Fedora rebuild consumed a newer DMG with SHA256
`e8d55e25c898224401f669400cfd50dd7e5f21b6cc501dd87f1396ecae3338e8`.
That input failed required patch gates, including tray quit, Fast model guard,
subagent metadata, and local conversation route hydration.

`scripts/developer/Build-CodexDesktopLinux.ps1` now accepts an explicit
`-UpstreamDmgPath` and `-DmgRefreshMode`. The corrected build pins the accepted
`617ea5af...` DMG instead of silently consuming a changed download.

=== Direct builds lost the Linux feature environment

The former direct `make build-app` path could write no feature config and let
`linux-features.js` report `None`, even when `CODEX_LINUX_FEATURES` was set.

The PowerShell build procedure now:

* discovers the selected Linux feature ids;
* writes `linux-features/features.json`;
* exports both `CODEX_LINUX_FEATURES` and `CODEX_LINUX_FEATURES_CONFIG`;
* verifies `.codex-linux/build-info.json` and
  `resources/codex-linux-build-info.json` after installation.

The accepted Debian, AlmaLinux, and Fedora payloads each report exactly 29
enabled features.

=== Already-adapted source trees replayed patches

The local Codex++ source tree was already adapted, but the installer attempted
to replay all snippets as though it were a clean upstream checkout. Later
in-tree edits can make both forward and reverse patch checks ambiguous.

`scripts/developer/Installer-and-Manager.ps1` now provides
`-SkipSnippetApply`. That switch skips replay but still runs
`Assert-SourceLinuxAdaptationApplied`, so an already-adapted tree remains
guarded before build.

=== Empty thread previews hid valid conversations

Some legacy Codex Desktop rows had valid rollout metadata and a non-empty
`first_user_message`, but an empty `preview`. Those rows could still satisfy
provider synchronization while remaining absent from the project conversation
index and appearing to the user as an empty project.

Compatibility patch `086-linux-thread-preview-backfill` fills only an empty
preview from a non-empty first-user message for visible user conversations. It
does not replace existing previews and includes the repair in transactional
update counts. The focused regression
`provider_sync_backfills_empty_thread_preview_from_first_user_message` passed.

=== DEB and RPM default entry bypassed Codex++

Final package validation found a separate integration defect:

* both packages contained `codex-plus-plus`, `codex-plus-plus-manager`, and
  `launch-codex-plus-plus`;
* `/usr/bin/codex-desktop` nevertheless executed `/opt/codex-desktop/start.sh`
  directly;
* ChatGPT launched successfully, but all three CDP pages reported a null
  `__CODEX_PLUS_VERSION__`;
* launching the same installed payload through the app-local Codex++ wrapper
  immediately produced `__CODEX_PLUS_VERSION__ = "1.2.41"` on all three pages.

Codex++ injection is a runtime CDP operation. Merely carrying the binaries in
the application directory is not enough.

The shared package launcher now behaves as follows:

[source,bash]
----
codex_plus_plus_launcher="/opt/codex-desktop/.codex-plusplus/install/launch-codex-plus-plus"
if [ -x "$codex_plus_plus_launcher" ]; then
    exec "$codex_plus_plus_launcher" "$@"
fi
exec /opt/codex-desktop/start.sh "$@"
----

The fallback preserves normal behavior for an upstream-only package without
Codex++. The RPM builder now calls the same `write_launcher_stub` helper as the
DEB builder instead of maintaining a second launcher implementation.

This correction belongs to the vendored `codex-desktop-linux` packaging
source, so it is committed directly with `scripts_smoke.sh` coverage. It is not
encoded as a Codex++ snippet patch that would target the wrong upstream tree.

== Build-line details

=== Fedora 43 modern payload

The Fedora payload was built in `codexpp-v141-fix0003-fedora-build` with the
native Fedora stack:

* WebKitGTK 4.1 and JavaScriptCoreGTK 4.1;
* libsoup 3;
* native Node.js, Rust, Cargo, 7-Zip, Xvfb, and xdotool;
* no Pixi or Conda runtime;
* no `LD_LIBRARY_PATH` WebKit 4.0 bridge;
* no `manager-runtime` directory;
* no `WEBKIT_DISABLE_COMPOSITING_MODE` validation override.

Xvfb, xdotool, and CDP validation produced a visible `ChatGPT` window and
three injected AppHost pages reporting Codex++ `1.2.41`.

=== AlmaLinux 9.8 compatibility payload

The AlmaLinux payload was rebuilt from the pinned accepted DMG in
`codexpp-v141-fix0003-alma-build`.

The Manager intentionally uses the EL9 compatibility path:

* WebKitGTK 4.0 and JavaScriptCoreGTK 4.0;
* libsoup 2.4;
* `$ORIGIN/manager-runtime` RUNPATH;
* 56 ELF files with a maximum `GLIBC_2.34` requirement;
* no missing dependencies with Conda variables and `LD_LIBRARY_PATH` cleared.

The old global Conda linker registration was disabled. Runtime checks resolve
the Manager WebKit libraries from the EL9 system and keep the small
`manager-runtime` compatibility directory available for appindicator fallback.

=== Debian 10 compatibility payload

The DEB uses the separately validated Debian 10 payload and its WebKitGTK 4.0
Manager. It is not reused for either portable archive. The final install used
`apt-get --no-install-recommends` so optional desktop helpers did not pull an
unrelated KDE and multimedia stack into the minimal validation container.

== Package-entry acceptance

The package launcher change was developed test-first. New DEB and RPM staging
assertions failed against the direct `start.sh` launcher, then passed after the
shared conditional launcher was implemented.

=== RPM

AlmaLinux 9 dependency-ready container. The earlier minimal-container run had
already resolved the complete EL9 dependency transaction.

Validation results:

* NEVRA: `codex-desktop-1.2.41-2.fix0003.el9.x86_64`;
* `rpm -V codex-desktop`: no differences;
* RPM digest verification: passed;
* default entry: `/usr/bin/codex-desktop`;
* process route: system entry -> `codex-plus-plus --app-path` -> Electron;
* visible X11 window: `ChatGPT`, 1280x820, WM class `codex-desktop`;
* CDP targets: 3 of 3 report `__CODEX_PLUS_VERSION__ = "1.2.41"`;
* Manager window: `Codex++ 管理工具`, 1180x820, complete Chinese rendering;
* clean Manager `ldd`: WebKitGTK 4.0, JavaScriptCoreGTK 4.0, libsoup 2.4,
  and no missing library.
