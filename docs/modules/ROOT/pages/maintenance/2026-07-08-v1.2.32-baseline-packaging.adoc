== Root Cause Findings

=== Fast / Standard injected toggle

The host report showing `当前模型未获取` came from the still-running and still-installed host Codex++ `1.2.28` injection, not from the newly validated container payload.

Fix carried into `v1.2.32`:

* the renderer service-tier fallback preserves explicit request/catalog priority;
* it canonicalizes visible upstream composer/footer labels such as `GPT-5.5` and `5.5 超高`;
* it still blocks Fast when an explicit unsupported model is known.

Validation:

* `codex-plus-core` `cdp_bridge` service-tier regression passed;
* container CDP reported `window.__CODEX_PLUS_VERSION__ = "1.2.32"`;
* isolated container login UI did not contain `当前模型未获取`.

=== Local conversations showing `暂无对话`

The remaining empty entries were caused by Codex Desktop local catalog and route hydration behavior after provider-sync backfill.

Fix carried into the Codex Desktop Linux snapshot:

* preserve provider-sync rollout-backed local catalog rows during pruning;
* patch the webview initial local thread snapshot;
* hydrate route-opened local conversations before resume.

Validation:

* `node --test scripts/patch-linux-window-ui.test.js` passed;
* descriptor coverage includes `linux-local-thread-catalog-preserve-backfill`, `linux-local-thread-catalog-initial-snapshot`, and `linux-local-conversation-route-hydration`;
* isolated container login UI did not show `暂无对话`.

== Linux Features `None`

The durable build procedure fix is to make the direct Codex Desktop `make build-app` path write an explicit local `linux-features/features.json`, export `CODEX_LINUX_FEATURES_CONFIG`, and validate both build-info files after install.

The local Podman PowerShell fixture now:

* writes the feature config before direct build;
* exports `CODEX_LINUX_FEATURES`;
* exports `CODEX_LINUX_FEATURES_CONFIG`;
* verifies `$HOME/opt/CodexDesktop/.codex-linux/build-info.json`;
* verifies `$HOME/opt/CodexDesktop/resources/codex-linux-build-info.json`.

The tracked workflow contract checks for this fixture behavior when `.podman-test/` exists, and the official maintenance workflow now documents this requirement.
