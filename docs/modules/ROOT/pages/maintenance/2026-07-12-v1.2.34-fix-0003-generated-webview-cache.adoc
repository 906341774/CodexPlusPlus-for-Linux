== Host failure

The final `fix-0002` host acceptance opened `Settings -> Linux desktop` and
reliably reached the React error boundary:

[source,text]
----
TypeError: Cannot read properties of null (reading 'useState')
----

CDP and the on-disk payload showed that the browser was executing two
different generations of the same fixed-name asset:

* the cached response was 12,560 bytes and contained the older hook-based
  `useLinuxSetting` implementation;
* the installed and current HTTP response was 15,289 bytes and contained the
  newer class-backed `LinuxToggle` implementation;
* the historical response had been stored with
  `Cache-Control: public, max-age=31536000, immutable`;
* the current server returned `Cache-Control: no-store, max-age=0`.

Changing the current response policy cannot invalidate an immutable response
that Chromium has already stored. Clean Podman homes therefore passed while a
real upgraded host could combine a stale generated module with current React
chunks.

This was not a Codex++ Fast-mode defect and was not introduced by the
`fix-0002` Portable Manager. It was an upgrade compatibility defect in
fixed-name generated Webview modules.

== Content-versioned generated assets

The new finalizer discovers every top-level Webview asset matching
`*-linux.js`, sorts the names, normalizes existing adapter cache queries, and
hashes each name and normalized content with SHA256. The first 16 hexadecimal
characters become a shared query value:

[source,text]
----
?codex-linux-cache=3c9d6b7f8424d3a7
----

The finalizer rewrites quoted static and dynamic imports in JavaScript assets.
It runs in `extracted-app:post-webview` at order `1000000000`, after all other
core and feature patches. A change to any generated Linux module rotates every
related URL, so a route module cannot retain a reference to a stale member of
the generated asset set.

The hash calculation removes the existing query before hashing. Reapplying the
patch is therefore idempotent instead of generating a new key on every run.

The accepted payload contains six generated Linux assets and six canonical
references. Recomputing the key from the installed files produced
`3c9d6b7f8424d3a7`; normalizing the completed payload required zero changes.

== Test-first evidence

The regression was first expressed as a runner test. Its red run failed
because generated asset imports had no `codex-linux-cache` query. The green
test verifies three behaviors:

* generated module references receive one 16-character key;
* a second run is byte-idempotent;
* changing one generated module rotates references to the entire set.

Descriptor discovery tests also require the finalizer to remain in the
post-Webview phase after the other post-Webview core patches.

The focused Node runs passed 354 core tests and 479 feature tests. The final
full regression passed:

* adapter workflow, distribution workflow, and installer selftest;
* 290 Codex++ core Rust tests;
* 19 Codex++ provider-sync tests;
* one Pure API Node contract;
* 880 Codex Desktop Node tests;
* the complete shell smoke suite and all 21 probe-equivalence scenarios.

== Rejected build and source drift gate

The first recovered build completed, but its patch report still contained 144
records. Comparison with the installed `fix-0001` payload showed that the new
cache finalizer had replaced, rather than accompanied, the required
`linux-app-server-initialize-timeout` record.

The container build source was missing exactly two source files from
`fix-0001`:

* `scripts/patches/core/all-linux/extracted-app/app-server/patch.js`;
* `scripts/patches/impl/main-process/app-server.js`.

That payload was rejected before packaging. The complete patch, feature,
packaging, and test source trees were compared by relative path and SHA256,
the missing files and two stale package/test files were synchronized, and the
pinned build was run once more.

The accepted payload records:

* 23 enabled Linux features in both build-info documents;
* 145 patches: 116 `applied` and 29 `already-applied`;
* both `linux-app-server-initialize-timeout` and
  `generated-webview-asset-cache-keys` as applied;
* zero required failures and zero post-patch integrity findings.

This check prevented the cache fix from silently regressing the previously
released 120-second cold-start initialize timeout.

== Portable lifecycle acceptance

The existing AlmaLinux 9 Portable test home started with the obsolete
`codex-desktop-portable.desktop` entry. Updating through the current Manager:

* replaced the 143-record older payload with the 145-record payload;
* removed the generic iconless entry;
* created only `codex-plus-plus.desktop` and
  `codex-plus-plus-manager.desktop`;
* assigned both entries the release icon and Portable ownership marker;
* created the three relocatable user command symlinks;
* left no incoming, work, or backup directory.

Seven external Codex and Codex++ data paths had identical existence state,
device number, inode, and type before and after the update. A subsequent
preserve-data uninstall and clean install recreated the application and both
menu entries while the same seven-path record remained byte-identical.

== Release relation and remaining host gate

`v1.2.34-fix-0003` supersedes the application payloads from `fix-0001` and
includes the current Portable Manager from `fix-0002`. Neither earlier tag is
moved.

The final host replacement must preserve the seven external data paths and
reuse the existing Chromium cache. Acceptance is complete only after the host
confirms Linux Settings without an error boundary, conversation hydration,
Codex++ Fast/Standard switching, the Manager, and exactly the two owned menu
entries.
