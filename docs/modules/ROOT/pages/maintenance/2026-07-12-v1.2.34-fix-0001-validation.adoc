immutable `v1.2.34` baseline. The fixes are published as the additive hotfix
tag `v1.2.34-fix-0001`; the existing `v1.2.34` tag is not moved.

== Baseline regressions carried into the packages

The package payload was rebuilt from the already validated `v1.2.34`
adaptation. It therefore retains the three user-visible baseline fixes:

* rollout-backed local conversations are cataloged, titled, preserved during
  scans, hydrated before navigation, and no longer rendered as empty
  conversation placeholders;
* the direct PowerShell build writes a concrete Linux feature config, exports
  both feature variables, enables every valid feature except `example-feature`
  and `local`, and verifies both generated metadata files;
* the Codex++ injected Fast/Standard control recognizes GPT-5.6 while retaining
  explicit unsupported-model rejection, and the upstream Speed control remains
  available.

Both final build metadata files contain the same 23 feature ids. The final
patch report contains 144 records: 115 `applied`, 29 `already-applied`, no
required failures, and zero post-patch integrity findings.

== Packaging failures and root causes

=== Debian 10 native compatibility

The first package payload was not genuinely Debian 10 compatible even though
the Electron application itself could run there. Two bundled native tools had
newer symbol requirements:

* the prebuilt X11 Computer Use helper was built on a newer distribution;
* the bundled browser-use `node_repl` executable retained GLIBC symbol versions
  above the Debian 10 ceiling.

`Build-CodexDesktopLinux.ps1` now resolves the X11 helper from a pinned source
repository and exact commit, stores it in an isolated build-source cache, and
passes the source path into the build. The Debian 10 build therefore compiles
the helper against glibc 2.28 instead of accepting an opaque newer binary.

The `node_repl` compatibility step is now a structured ELF patcher backed by a
small native fallback object. It rejects unknown high-version symbols, keeps
the supported fallback symbols weak, rewrites only their version bindings, and
is idempotent. It does not perform a broad byte substitution.

The release compatibility gate scans every x86-64 ELF file. The installed DEB
and RPM payloads each contain 40 checked ELF files; the Portable payload
contains 44 because it also carries the Manager runtime. Every checked file
requires at most `GLIBC_2.28`.

=== Codex++ Manager on stable distributions

Current Codex++ Manager sources target WebKitGTK 4.1 and libsoup 3, which are
not available on Debian 10 and are not the default ABI on the RHEL 9 package
baseline used here. Merely changing package dependency names would leave the
Manager unbuildable or dynamically unresolved.

The installer now chooses the Manager ABI explicitly:

* use native WebKitGTK 4.1 when all required development modules exist;
* otherwise build through a verified WebKitGTK 4.0/libsoup 2.4 compatibility
  bridge;
* fail with a concrete dependency error when neither ABI is complete.

The 4.0 path provides only the newer symbols used by the Manager, verifies the
resulting ELF SONAMEs, installs its appindicator compatibility runtime beside
the Manager, and sets a relative RUNPATH. Package metadata declares the actual
WebKitGTK 4.0, JavaScriptCoreGTK 4.0, and libsoup 2.4 runtime dependencies.

=== First-start app-server timeout

In a genuinely clean home directory, the Codex CLI may synchronize its plugin
marketplace before answering the Desktop initialize request. The original
30-second Desktop timeout expired while that valid first synchronization was
still running. Installing `git` removes the slower HTTP fallback, but the clean
Debian 10 acceptance run still needed 36,776 ms for the initialize handshake.

The packages now require `git`, and a `required-upstream` Desktop patch changes
only the unique initialize timeout constant from 30 to 120 seconds. The patch
is signature-guarded, idempotent, and fails closed if the upstream bundle shape
becomes ambiguous. Adjacent 30-second and 90-second timeouts are untouched.

=== RPM CJK rendering

The AlmaLinux 9 minimal image has no CJK font by default. The Manager itself
was healthy, but Chinese labels rendered as replacement boxes. The RPM now
recommends `google-noto-sans-cjk-ttc-fonts`. A normal `dnf install` pulled the
font package automatically, and the final Xvfb screenshot rendered the Chinese
interface correctly.

=== Runtime dependency cleanup

Updater-disabled packages no longer retain packaging-only toolchain
dependencies. The DEB builder removes `build-essential`, `dpkg`, `p7zip-full`,
`unzip`, and policy-kit requirements when the local updater is disabled. The
RPM keeps build tools behind the updater condition while retaining only the
runtime dependencies needed by the installed payload.

== Clean installation validation

=== Debian 10 DEB

A clean `debian:10` container installed the DEB through the normal package
manager. Package ownership and integrity, exact payload hashes, 23-feature
metadata, 144 patch records, GLIBC ceiling, and Codex++ entrypoints all passed.
The cold GUI launch completed the 36,776 ms initialize handshake without a
timeout and exposed the expected Codex windows. The WebKitGTK 4.0 Manager also
launched successfully.

=== AlmaLinux 9 RPM

A fresh `almalinux:9-minimal` container installed the final RPM with `dnf`.
The transaction installed the declared CJK weak dependency. RPM integrity and
ownership, exact payload hashes, feature metadata, patch report, GLIBC ceiling,
cold GUI launch, three Codex CDP pages, and the WebKitGTK 4.0 Manager all
passed. Chinese labels were visually checked after the font fix.

=== Portable 7z

The Portable archive was validated as an ordinary `qa` user in a separate
AlmaLinux 9 minimal container. The following lifecycle passed:

* install into `$HOME/.local/opt/CodexDesktop` and create relocatable user
  command and desktop integration;
* launch Codex Desktop through the user-level symlink;
* perform an atomic update while removing an application marker and preserving
  user-data sentinels;
* uninstall with the default preserve-data policy and verify that application,
  symlinks, desktop entry, and manager state were removed while user data
  remained;
* reinstall, launch the Codex++ Manager on isolated Xvfb, and verify complete
  Chinese rendering;
* uninstall with `-PurgeUserData` and verify all application, integration,
  config, state, cache, and user-data paths were absent.

The disposable Portable validation container was removed after the final
purge check. The Codex++ Manager screenshot is a GUI launch and rendering
check; it is not a claim that account-dependent health checks pass in an empty
test home.

== Regression gates

The focused red/green tests cover the timeout signature and routing, X11
source pinning, Manager ABI bridge and runtime, GLIBC ceiling, package runtime
dependencies, CJK weak dependency, feature metadata, and Portable lifecycle.

The final pre-publication rerun from the completed worktree passed:

* adapter workflow, distribution workflow, and installer selftest;
* 290 Codex++ core Rust tests;
* 19 provider-sync Rust tests;
* one Pure API Node contract test;
* 879 Codex Desktop Node tests;
* the complete Codex Desktop shell smoke suite, including all 21 behavioral
  equivalence scenarios.

The full log remains under the ignored adaptation evidence directory as
`fix0001-final-regression.log`.

== Known limits

* The packages and archive are SHA256-identified but are not signed by a
  distribution in this iteration.
* Clean-container GUI checks use isolated Xvfb and an unauthenticated home;
  account- and subscription-dependent remote services are outside this gate.
* Host replacement is performed only after the tag and GitHub Release assets
  are successfully published, so release failure cannot replace the working
  host with an unpublished payload.
