:toc:

English | xref:snippets_zh-CN.adoc[简体中文]

This page is both documentation and installer input.
The table is intended for maintainers; the JSON manifest is parsed by `scripts/developer/Installer-and-Manager.ps1`.

== Patch categories

Compatibility patches under `docs/modules/ROOT/attachments/patches/compatibility/` are required for the Linux port. Enhancement patches under `docs/modules/ROOT/attachments/patches/enhancements/` are optional user-selectable features.

== Snippet table

[cols="1,1,2,3,2,2", options="header"]
|===
|ID |Default |Target |Purpose |Injection condition |Attachment

|`010-linux-app-paths`
|Required
|`crates/codex-plus-core/src/app_paths.rs`
|Recognize Linux `start.sh` as the Codex executable, read the Linux wrapper `version` file, and recover the real app root from adapter desktop entries when stale `codex-app` state is present.
|Needed when upstream does not natively identify the `ilysenko/codex-desktop-linux` app layout.
|xref:attachment$patches/compatibility/010-linux-app-paths.patch[patch]

|`020-cdp-multi-target-injection`
|Required
|`crates/codex-plus-core/src/cdp.rs`, `apps/codex-plus-launcher/src/main.rs`
|Inject all live Codex webview page targets while preferring the primary window over the hotkey window.
|Needed when Linux webview exposes several unlabeled CDP page targets or the first target is not the main window.
|xref:attachment$patches/compatibility/020-cdp-multi-target-injection.patch[patch]

|`030-linux-launcher-environment`
|Required
|`apps/codex-plus-launcher/src/main.rs`, `crates/codex-plus-core/src/launcher.rs`, `crates/codex-plus-core/src/watcher.rs`
|Launch Linux Codex Desktop through `start.sh`, preserve resolver/proxy environment, remove Electron poison variables, set safe webview ports, allow Chromium private-network helper preflights, expose helper HTTP bridge routes for settings/user scripts, keep the Linux wrapper alive after injection failure, and clear stale Linux launcher/helper processes before restart.
|Needed for the hacked Linux Codex Desktop wrapper, reliable DNS/proxy behavior in desktop sessions, Codex webview access to Codex++ helper state when CDP binding is missing or reconnecting, and recovery from stale helper ports left by crashed launcher processes.
|xref:attachment$patches/compatibility/030-linux-launcher-environment.patch[patch]

|`040-linux-entrypoints-health`
|Required
|`crates/codex-plus-core/src/install/mod.rs`, `apps/codex-plus-manager/src-tauri/src/commands.rs`, `apps/codex-plus-manager/src-tauri/src/install.rs`
|Make manager health checks detect adapter-local Linux launcher and manager binaries under `codex-app/.codex-plusplus/install`, while preserving upstream-style Codex++ desktop entry names.
|Needed when the manager reports static launch entry or management tool entry as missing on Linux.
|xref:attachment$patches/compatibility/040-linux-entrypoints-health.patch[patch]

|`050-pure-api-config-sync`
|Required
|`crates/codex-plus-core/src/relay_config.rs`, `apps/codex-plus-manager/src/App.tsx`
|Make Pure API mode write `requires_openai_auth = false`, preserve hostname BaseURL values, upgrade plain HTTP public hostnames to HTTPS, and re-apply `$HOME/.codex/config.toml` whenever the active API profile changes.
|Needed when switching API profiles in Codex++ does not update Codex Desktop immediately.
|xref:attachment$patches/compatibility/050-pure-api-config-sync.patch[patch]

|`060-renderer-linux-compatibility`
|Required
|`apps/codex-plus-manager/src/App.tsx`, `apps/codex-plus-manager/src/i18n-en.ts`, and the three renderer injection assets
|Stabilize Linux renderer injection for plugin marketplace requests/details, Pure API synthetic accounts, delete behavior, floating-control placement, and Fast/Standard switching. Fast supports GPT-5.4, GPT-5.5, GPT-5.6, GPT-5.6 model suffixes, localized labels, and Linux composer-footer discovery; transient backend checks do not block a known local model, and Codex++ cleanup leaves the official Fast control untouched. This patch deliberately does not restore the removed sidebar-entry unlock, ChatGPT authentication spoofing, or disabled-button mutation.
|Needed while upstream renderer injection does not account for Linux Codex Desktop DOM and MCP response differences.
|xref:attachment$patches/compatibility/060-renderer-linux-compatibility.patch[patch]

|`070-linux-user-scripts-compatibility`
|Required
|`crates/codex-plus-core/src/user_scripts.rs`
|Wrap enabled user scripts with a Linux Codex Desktop location alias so marketplace scripts that expect the upstream `app://-/index.html` renderer URL still run on the Linux localhost webview.
|Needed when user scripts such as `Codex Context Used Meter` treat the Linux `http://127.0.0.1:<port>/?mcpAppSandboxDevtools=1` page as a non-conversation window.
|xref:attachment$patches/compatibility/070-linux-user-scripts-compatibility.patch[patch]

|`080-linux-local-thread-catalog-sync`
|Required
|`crates/codex-plus-core/src/codex_sqlite.rs`, `crates/codex-plus-data/src/provider_sync.rs`
|Backfill Codex Desktop `local_thread_catalog` rows from real rollout sources while preserving non-empty titles, excluding projectless threads, and avoiding revision/sequence or backup churn when no data changed. The pinned CodexDesktop source snapshot adds companion initial-snapshot, pruning-preservation, and direct-route hydration patches.
|Needed when Codex++ can list local sessions but Linux Codex Desktop project sidebars show no conversations, when source-less remote catalog rows remain visible as empty history entries, or when shown conversations never load after click, after a Codex storage schema update.
|xref:attachment$patches/compatibility/080-linux-local-thread-catalog-sync.patch[patch]

|`085-linux-workspace-state-paths`
|Required
|`crates/codex-plus-core/src/codex_app_state.rs`
|Preserve POSIX separators in Codex Desktop state and narrowly repair legacy Codex++ local-project records whose id was hashed from a backslash path and whose `rootPaths` stayed empty.
|Needed when a Linux workspace appears under a malformed project id and its project sidebar cannot resolve the real POSIX root.
|xref:attachment$patches/compatibility/085-linux-workspace-state-paths.patch[patch]

|`086-linux-thread-preview-backfill`
|Required
|`crates/codex-plus-data/src/provider_sync.rs`
|Backfill an empty Codex Desktop thread `preview` from its non-empty `first_user_message` for visible user conversations, without replacing an existing preview, and include the repair in transactional update counts.
|Needed when legacy rows already have valid rollout metadata and first-user text but remain absent from the project conversation index because `preview` is empty.
|xref:attachment$patches/compatibility/086-linux-thread-preview-backfill.patch[patch]

|`087-linux-restart-process-tree`
|Required
|`crates/codex-plus-core/src/watcher.rs`
|Make Linux Manager restart terminate the complete Codex++ launcher descendant tree, deepest children first, and reclaim Electron or Crashpad processes from the same Desktop root after they are reparented to PID 1. The current Manager and its `.codex-plusplus` management tree remain protected.
|Needed when **Restart Codex++** leaves an orphan authority, a stale shared app-server lock, or a reparented Electron process holding the configured CDP port, including after the old launcher has exited completely.
|xref:attachment$patches/compatibility/087-linux-restart-process-tree.patch[patch]

|`100-browser-native-rehosting`
|Enabled enhancement
|Codex++ launcher, Manager, gateway core, browser shim, and focused tests
|Run the original Codex Desktop React UI in a normal browser through an authenticated loopback gateway while reusing the server-side Electron AppHost and Codex++ Pure API/API Key state.
|Enable for headless Linux servers that need a browser-resizable DOM instead of VNC or pixel streaming. Runtime activation remains explicit and preserves normal foreground launch paths.
|xref:attachment$patches/enhancements/100-browser-native-rehosting.patch[patch]

|`900-regression-tests`
|Optional
|The focused compatibility test files and aggregate test configuration under `apps/codex-plus-manager`, `crates/codex-plus-core/tests`, and `crates/codex-plus-data/tests`
|Add regression coverage for the compatibility patches, including GPT-5.6 Fast/Standard variants, coexistence with the official Fast control, Linux user-script URL aliasing, restart process-tree cleanup, real-title catalog backfill, empty thread-preview repair, idempotent catalog sync, and projectless exclusion.
|Recommended for source builds and CI; can be disabled for a faster production-only patch.
|xref:attachment$patches/compatibility/900-regression-tests.patch[patch]
|===
